# B站之手 · 规划

> 状态：P1/P2 已完成并真机验证（点赞/投币/收藏/评论）；P3 已发布 GitHub，回归继续
> 插件标识：`astrbot_plugin_bilibili_hand`
> 上游依赖：`astrbot_plugin_bilibili_eyes`

## 1. 定位

B站之眼负责“看”，B站之手负责“做”。

- 手只能操作**当前会话里 B站之眼上一次刚看过的那个视频**；
- 不接收任意 BV/链接，不做批量、定时、多账号轮换；
- 所有动作真实作用于配置的 B 站账号，有封号/风控/内容风险；
- 默认只允许 AstrBot 管理员和 `allowed_users` 白名单使用。

## 2. 已确认的产品规则

| 动作 | 触发 | 目标 | 开始反馈 | 结束反馈 |
| --- | --- | --- | --- | --- |
| 点赞 | bot 自主决定 | 上次视频 | **不发**开始消息 | 结果交给 LLM 组织语言 |
| 投币 | `/手投币 [1\|2]` 指令 | 上次视频 | 发预制消息 | 直接结果反馈 |
| 收藏 | 指令 `/手收藏` | 上次视频 | 发预制消息 | 结果交给 LLM 组织语言 |
| 评论 | 指令 `/手评论 <要求>` 或自然语言 | 上次视频 | 发预制消息 | 预览 → 确认 → 执行 → 结果交给 LLM |

补充：

- 点赞是“看完视频后的自主行为”，不产生“我去了”的中间消息；
- 投币不可逆，改成指令触发，由用户明确决定 1 枚或 2 枚；
- 收藏和评论由用户指令触发，所以保留开始反馈；
- 评论内容由 bot 自己生成，用户只给自然语言要求；
- 所有失败都返回语义原因，禁止把 B 站原始错误码直接交给用户；
- 处理动作期间用户再发指令，要返回“正在操作，稍等”的提示。

## 3. 依赖与桥接

### B站之眼新增公开方法

```python
def get_last_video(self, umo: str) -> dict | None:
    """返回最近 30 分钟内看过的视频；UP 主页不算。"""
```

返回：

```python
{
    "bvid": "BV...",
    "aid": 123,
    "cid": 456,
    "page": 1,
    "title": "...",
    "up_uid": 789,
    "up_name": "...",
    "watched_at": 1760000000.0,
    "digest": "...",
}
```

约束：

- 只读，不触发重新抓取；
- 只返回 `kind == "video"` 的会话材料；
- 超过 30 分钟返回 `None`；
- 手插件不得访问眼睛的私有字段，只能调用这个方法。

### 手插件取依赖

```python
meta = context.get_registered_star("astrbot_plugin_bilibili_eyes")
eye = meta.star_cls if meta and meta.activated else None
```

- 眼睛未安装/未激活：手插件显示“请先安装并启用 B站之眼”，不注册真实动作；
- 不通过 `import` 眼睛源码建立硬耦合，避免插件加载顺序和热重载问题。

```text

```

### 反馈链路

- 开始反馈（收藏/评论）：`event.send(MessageChain([Plain(...)]))`，纯文本；
- 结束反馈：收藏/投币/评论命令在命令内直接发送结果；自主点赞的结果由工具返回给主模型。
- 不在 `request_llm` 后调用 `stop_event`；
- 纯指令（`/手状态`）直接发送后停止；
- 动作执行走独立 `ThreadPoolExecutor`。

## 5. 权限与安全

- `enabled` 总开关；
- 管理员 + `allowed_users` 白名单；
- 非授权用户直接拒绝，不调用 LLM；
- Cookie 配置独立于眼睛，不写日志；
- 每日动作上限：点赞/投币/收藏/评论分别计数；
- 同一视频 24 小时内不重复动作；
- `dry_run` 首次默认开启；
- 风控 `-352/-412/-509` 进入冷却；
- 评论验证码直接中止，不绕过；
- 审计日志不含 Cookie。

| 点赞 | `POST /x/web-interface/archive/like` |

`need_login` / `csrf` / `rate_limited` / `captcha` / `sensitive` /

`no_target` / `network`。

## 9. P2 评论（已实现，待真实回归）

### 9.1 产品规则

- 只评论 `get_last_video(umo)` 返回的上次视频；
- 触发方式：
  - 指令：`/手评论 <自然语言要求>`；
  - 自然语言：`给这个视频评一句……`、`评论一下……`、`发条评论……`；
- 评论内容由 bot 自己生成，用户只给要求，不直接提供评论文本；
- 默认先生成预览，用户确认后再发布；
- 发布时发开始预制消息；发布结果通过 `on_llm_request` 注入主模型，
  由主模型用自己的话告诉用户；
- 失败只给语义原因，不给 B 站错误码；
- 默认只允许管理员 + 白名单。

### 9.2 评论草稿生成

新增 `hand_comment.py`：

```python
async def draft_comment(context, umo, target, requirement) -> str
```

- 取当前会话人格提示词（`context.persona_manager`）作为语气基础；
- 输入：目标视频标题 + 上次视频 digest + 用户自然语言要求；
- 约束：
  - 中文、1~3 句、不超过 120 字；
  - 不输出 Markdown、编号、引号包裹；
  - 不编造视频里没有的内容；
  - 不写“这个视频/这段我看了”等总结式开头；
  - 只输出评论正文，不解释。
- 生成后由插件清洗：去代码块/首尾引号/多余空行，超长截断，空文本失败。

### 9.3 预览与确认

```text
/手评论 说点鼓励的话
→ 预制消息：我想想怎么评…
→ 生成草稿
→ 预览：
   我想发这条评论：
   「……」
   /手评论确认  发布
   /手评论取消  取消
   120 秒内有效
```

- 预览存 `_pending_comment[umo] = {target, text, expires, sender}`；
- 确认时校验：
  - 同一个人；
  - 未过期；
  - `get_last_video` 仍是同一个 `bvid/page`；
  - 尚未超过评论每日上限；
- `/手评论确认` 在命令层只登记 `pending`，在 `on_llm_request` 里发开始消息、
  调用评论接口、注入结果（避免 `_has_send_oper` 跳过 LLM）；
- `comment_require_confirm=false` 时可跳过预览，但开始/结果反馈和限额仍保留。

### 9.4 评论接口

`hand_client.py` 新增：

```python
def comment(aid, message, root=0, parent=0) -> dict
def delete_comment(aid, rpid) -> dict   # 后续可选，当前未实现
```

- 发表评论：`POST /x/v2/reply/add`
  - `type=1`, `oid=aid`, `message`, `plat=1`, `csrf`；
- 删除评论：`POST /x/v2/reply/del`（发布后 120 秒内可用，需 `rpid`）；
- 错误映射：
  - `12002` 评论区关闭；
  - `12015` 需要验证码，直接中止；
  - `12016` 敏感内容；
  - `12025` 字数过多；
  - `12051` 重复评论；
  - `12035` 被 UP 拉黑；
  - `-111` CSRF；
  - `-352/-412/-509` 风控。

### 9.5 自然语言触发

- 只在以下条件同时满足时识别：
  - 管理员/白名单；
  - 当前会话有上次视频；
  - 消息含明确评论意图：`评论`、`评一句`、`发条评论`、`说点什么`；
- 不把普通“评论区……”讨论当成评论请求；
- 识别后直接走与 `/手评论` 相同的草稿流程；
- 处理期间按 `on_waiting` 提示，避免并发。

### 9.6 限额与审计

- `max_comments_per_day` 独立计数；
- 同一视频 24 小时内只评论一次；
- 两条评论至少间隔 120 秒；
- 审计记录：操作者、目标、评论正文、rpid、结果；
- 评论正文不写日志全文，只写前 40 字 + 长度。

### 9.7 测试

- 每日上限、单视频去重；

## 11. 已知坑

- B站 DNS 会优先返回 IPv6，必须只走 IPv4；
- 纯指令不能统一 `stop_event` 后再 `request_llm`；
- 用户命令不要在 `on_llm_request` 里执行，否则会被 debounce 等插件截断；命令内直接执行并反馈；
- 热重载要清理 `hand_client` 等子模块；
- Cookie/CSRF 错误不能让用户看到原始 code；
- 自主点赞不发送开始预制消息，只发最终 LLM 回复；
- 投币/收藏/评论是用户命令，必须在命令内直接执行并反馈。
